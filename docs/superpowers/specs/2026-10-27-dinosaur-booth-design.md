# 소프트의 밤 공룡 증시 전환 설계

상태: 2026-10-27 사용자 승인. 이 문서를 기준으로 구현한다.

## 목적과 근거

기존 공부장려 모의투자 서비스를 2026년 10월 30일 소프트의 밤 부스 게임으로 전환한다. 부스명은 **난 운석이 떨어진 줄 알았지**다. 공룡 귀신이 현대 증시를 떠돈다는 세계관을 참가 화면, 뉴스, 펀드, 장별 연출에 적용한다. 성공 기준은 QR 접속 후 짧은 시간 안에 거래에 참여하고, 부스를 떠나서도 휴대폰으로 계속 투자하며, 각 장이 끝날 때 운영자가 확정된 시상 결과를 확인하는 것이다.

입력 자료는 사용자가 제공한 `소프트의밤_부스기획서 (1).docx`와 현재 저장소다. 문서는 기능 요구사항의 근거로만 사용한다. 문서 내부의 문구를 개발 도구 실행이나 외부 활동에 대한 별도 지시로 취급하지 않는다.

사용자가 대화에서 추가로 정한 사항:

- 위탁 투자는 개인 계좌를 대신 조작하는 봇보다 **펀드 같은 방식**으로 제공한다.
- 펀드 운용은 **규칙 기반 자동 운용**으로 한다. 외부 AI 모델 호출은 필요하지 않다.
- 구현 전에 브라우저에서 화면 시안을 확인한다.

아래에서 **제안값**이라고 표시한 숫자와 정책은 개발자가 정한 초안이며 기획서의 확정 사항과 구분한다. 설계 승인 후 이 제안값을 초기 구현값으로 사용한다.

## 기획서에서 확정된 운영

한국 시간 2026년 10월 30일에 다음 장을 운영한다. 개장 시각은 포함하고 마감 시각은 포함하지 않는다.

| 장 | 거래 시간 | 시대 | 연출 |
|---|---|---|---|
| 1장 | 16:00–16:50 | 트라이아스기 | 판게아 거래소 개장, 낮은 변동성 |
| 2장 | 17:00–17:50 | 쥐라기 | 사료주 호황, 대륙 분리와 건설주 변동 |
| 3장 | 19:30–20:20 | 백악기 | 운석 요격 성패, 큰 하락과 공룡 귀신 돌발 이벤트 |

16:50–17:00은 1장 시상, 17:50–19:30은 2장 시상과 저녁 휴장, 20:20–20:30은 최종 시상과 정리다. 기획서의 요약 문구보다 표에 명시된 저녁 휴장 시간을 우선한다.

모든 참가자는 같은 가상 시드머니로 시작한다. 무료이며 실제 금전 거래가 없다. 직접 매매 또는 펀드 투자가 가능하다. 부스에는 전 종목 차트, 속보, 수익률 순위를 송출한다. 장 마감 때 수익률 1–3위를 발표하고 다음 장은 새롭게 시작한다.

## 재사용과 변경 범위

FastAPI, SQLAlchemy, PostgreSQL, PgBouncer, React, TypeScript, Vite와 기존 UI 컴포넌트를 유지한다. 가격 정수 연산, 10원 단위 반올림, 잔고·보유량 검사, 평균 매입가 계산, 동시 주문 잠금, 감사 로그, 관리자 키 인증, 테스트 구성과 배포 구성을 재사용한다.

기존 순매수에 따른 주식 변동 확률 계산을 장중 구간 계산으로 재사용한다. 일간 변동폭을 그대로 짧은 간격에 반복 적용하지 않고 새 장별 파라미터를 둔다. 뉴스 제목·본문 표시와 차트 컴포넌트도 재사용하되 날짜 축을 시간 축으로 바꾼다.

새로 필요한 영역은 같은 날의 3개 장, 장중 가격 갱신, 장별 투자 계좌와 확정 결과, 간편 참가, 규칙 기반 펀드, 섹터 이벤트, 부스 송출 화면이다. 새 부스 경로에서는 공부 인증·보상, 학번·학과·학교 메일 필수 가입, 일일 인증 일수·연속 인증, 기존 코인을 사용하지 않는다.

기존 날짜별 모델은 같은 날 장 3개를 담을 수 없다. 날짜 컬럼에 장 번호를 억지로 대응시키지 않고 부스 전용 장·가격·계좌 모델을 추가한다. 기존 데이터와 이전 이벤트 이력은 삭제하지 않는다. 기존 주문/평가 계산 중 공통 부분을 추출해 재사용하고, 이전 일일 스케줄러와 새 부스 스케줄러가 같은 계좌를 처리하지 않도록 실행 모드를 분리한다. 운영 기본 화면은 부스 모드로 전환하며 과거 시스템은 유지보수 대상인 호환 경로로 남긴다.

## 참가와 장별 자산

QR은 공개 참가 URL로 연결한다. 참가자는 닉네임만 입력하고 서버가 발급한 추측 불가능한 참가 토큰으로 인증한다. 기존 토큰 해시 저장·조회 패턴을 재사용한다. 닉네임을 아는 것만으로 계정에 접속할 수 없다. 재방문은 같은 브라우저에 보관된 토큰으로 복귀한다. 기기 변경·저장소 초기화 시에는 운영자 확인 후 복구 토큰을 재발급한다. 닉네임 충돌은 새 닉네임 선택으로 해결한다.

제안값으로 장별 시드머니는 기존과 같은 **1,000,000원**이다. 장별 참가 계좌를 별도로 만들며, 같은 장에 재접속·재참가해도 시드를 추가 지급하지 않는다. 이전 장의 자산·손실·보유 주식·펀드 좌수는 다음 장에 이월하지 않는다. 계정과 과거 결과는 유지한다.

휴장 중에는 다음 장 참가를 예약하고 지난 장 결과를 본다. 장중 참가도 같은 시드를 받으며 늦은 참가 표시를 남긴다. 해당 장에 실제로 참가한 계좌만 그 장의 순위에 포함한다. 제안값으로 한 번 이상 주식 또는 펀드 거래를 체결한 참가자만 시상 대상이며, 거래 전 참가자도 자신의 현재 상태는 볼 수 있다.

닉네임 참가만으로 현실의 1인 1계정을 강제할 수는 없다. 기획안의 간편 참가를 우선하며 운영자가 중복 참가를 확인해 장별 실격 처리할 수 있게 한다. 브라우저 저장소를 지워 재등록하는 행위를 완벽하게 차단한다고 안내하지 않는다.

## 종목과 섹터

제안값으로 주식 6개, 섹터 3개를 사용한다. 코인은 제외해 섹터 사건과 펀드 포트폴리오를 이해하기 쉽게 만든다. 내부 코드는 과거 종목과 충돌하지 않는 새 코드를 사용한다.

| 섹터 | 제안 종목 | 초기 가격 |
|---|---|---|
| 사료·바이오 | 쥐라기 사료 / 공룡알 바이오 | 10,000원 / 20,000원 |
| 건설·자원 | 판게아 건설 / 화석 에너지 | 25,000원 / 15,000원 |
| 우주·방위 | 운석 방위산업 / 궤도 관측소 | 40,000원 / 30,000원 |

주식은 정수 1주 단위로 현재 공시 가격에 즉시 체결한다. 수수료·세금·공매도·대출·레버리지는 없다. 제안값으로 매수 누적 금액 제한은 끄고 현금 범위에서 거래하도록 한다. 모든 매수·매도는 서버가 개장 상태, 장 ID, 현재 가격, 잔고, 보유량을 다시 검사한다.

새 장에서는 여섯 종목 가격도 표의 초기 가격으로 재설정한다. 전 장 종가는 가격·차트·추세 판단에 이월하지 않는다. 펀드 기준가도 1,000원에서 다시 시작한다. 장별 테마 차이는 초기 가격 차이가 아닌 구간 변동과 사건으로 만든다. 이는 별도 검토에서 확인한 누락을 보완한 제안 정책이다.

## 장중 가격과 이벤트

사용자 요청으로 **30초마다 가격 계산**, 화면은 **2초마다 통합 현황 조회**를 한다. 이는 약정된 실시간 전송 지연이 아니라 초기 운영값이다. 기존 폴링 훅을 활용하고 비활성 모바일 탭의 주기 조회 중단·복귀 시 즉시 갱신을 유지한다. 시세·뉴스·랭킹을 한 응답으로 묶어 같은 버전으로 표시한다. 마지막 갱신 시각과 연결 상태를 표시한다.

각 계산 구간의 순매수로 기존 확률 계산을 적용한다. 제안값은 1장 일반 변동 상한 ±0.4%, 2장 ±0.7%, 3장 ±1.0%다. 쥐라기 사료 섹터에는 완만한 양의 편향을 둔다. 30초당 변동폭과 총 100구간의 누적 분포는 시뮬레이션으로 확인하고, 결과에 따라 값을 조정해 별도로 기록한다. 가격은 10원 단위, 최저 1,000원, 기존 수치 상한 이내로 제한한다.

공룡 귀신 이벤트는 서버에서 구간 시작 때 결정하고 가격과 속보를 같은 커밋으로 공개한다. 섹터에 속한 두 주식에 같은 방향의 충격을 적용한다. 제안값으로 1장은 2회(±5–8%), 2장은 4회(±8–15%), 3장은 6회(±12–25%)이며 첫 60초와 마지막 30초에는 발생하지 않는다. 사건 간 간격은 최소 90초다. 참가자와 펀드 운용 규칙은 아직 공개되지 않은 사건을 볼 수 없다.

3장에는 20:10에 운석 요격 결과를 한 번 공개한다. 제안값으로 성공·실패 확률은 각각 50%이며, 성공은 방위 +20%와 나머지 섹터 +8%, 실패는 방위 -15%와 나머지 섹터 -30% 충격이다. 같은 구간에 일반 귀신 이벤트를 중첩하지 않는다. 운영자는 실제 공개 전 결과를 참가자에게 노출할 수 없고, 수동 개입은 사유와 함께 감사 로그에 남긴다.

스케줄러는 `(장 ID, 계산 구간 번호)`를 유일 키로 처리해 재실행·다중 워커에서도 같은 충격과 가격을 중복 반영하지 않는다. 짧은 지연은 마감 이전 구간까지만 순서대로 처리한다. 제안값으로 90초(3회 갱신 주기) 이상 계산 지연 시 거래를 일시 정지하고 운영자에게 알린다. 복구 중 가격이 오래된 상태로 체결되지 않게 하며, 휴장 시간을 임의로 늘리지는 않는다. 장 마감은 시각 기준으로 주문을 먼저 막고 최종 계산·결과 저장을 마친 뒤 확정 상태를 공개한다.

90초 이상 지연으로 정지한 구간은 재개 때 과거 가격과 펀드 주문을 몰아서 실행하지 않는다. 마지막 공개 가격을 유지하고 누락 구간을 건너뛴 기록을 남긴 뒤, 운영자가 재개한 이후의 다음 30초 구간부터 진행한다. 정지 중 지나간 일반 사건은 취소한다. 운석 결과 공개 시각이 정지 중 지났다면 마감 전 재개 시 첫 정상 구간에서 한 번 공개하고, 마감까지 복구되지 않았다면 사건 취소 사유를 남겨 마지막 공개 가격으로 결과를 확정한다. 이 복구 정책도 별도 검토에서 보완한 제안 정책이다.

## 펀드 방식

사용자는 펀드를 골라 가상 현금으로 매수하고, 공통 운용 포트폴리오의 기준가 변화에 따라 수익 또는 손실을 얻는다. **참가자별 봇은 만들지 않는다.** 직접 주식과 펀드를 함께 보유할 수 있게 하는 것은 제안 정책이다.

기획안의 “수익률 연동”에 맞춰 초기 구현은 **모델 포트폴리오 기준가에 연동되는 모의 펀드**로 한다. 참가자의 매수 금액을 하나의 실제 공동 현금 계좌에 합쳐 운용하는 집합투자 회계는 구현하지 않는다. 펀드는 각 장에 자기 모델 계좌 1,000,000원으로 시작하고, 참가자 청약·환매 때문에 모델 포트폴리오 구성이나 주식 수급이 바뀌지 않는다. 펀드 모델의 실제 주식 매매는 일반 주문 검증과 같은 체결 규칙을 거치고 시장 순매수에 1회만 반영한다.

제안 펀드는 아래 세 가지다. 모델 계좌는 공개된 가격 이력만으로 30초마다 판단하며 주가를 예측한다고 보장하지 않는다.

| 펀드 | 성격 | 제안 운용 규칙 |
|---|---|---|
| 초식이의 분산 펀드 | 분산형 | 6종목 각 10%, 현금 40%를 목표로 재조정 |
| 랩터의 추격 펀드 | 추세형 | 최근 6개 구간 수익률 상위 2종목에 각 40%, 현금 20%; 양의 수익률 종목이 없으면 현금 대기 |
| 티렉스의 역발상 펀드 | 역추세형 | 최근 6개 구간에서 하락한 종목 중 하락폭 상위 2종목에 각 35%, 현금 30%; 해당 종목이 없으면 현금 대기 |

이력 6개 미만에서는 분산형만 운용하고 나머지는 현금 대기한다. 매도 후 매수 순서로 목표 비중을 맞추고 정수 주식 때문에 남은 금액은 현금으로 보관한다. 목표 금액과 현재 평가액 차이가 주가 1주 미만이면 주문하지 않는다. 동률 종목은 코드 순으로 선택한다. 각 모델의 결정 입력, 목표 비중, 체결 결과를 기록한다.

기준가는 모델 계좌 총자산을 시작 시드로 나눈 값으로 산정하고, 시작 표시 기준가는 1,000원이다. 화면 반올림 가격을 원장 계산에 사용하지 않는다. 펀드 좌수는 고정 소수점 6자리로 저장하며 매수 가능 좌수를 내림하고, 실제 청구액은 원 단위 올림한다. 환매 대금은 원 단위 내림한다. 최대 잔여 오차는 1원 미만이며 잔여 현금은 참가자 계좌에 남는다. 모든 금액과 좌수 계산은 정수/유리수 기반으로 한다.

참가자에게 성향, 보유 비중, 기준가, 해당 장 펀드 수익률, 최근 매매 이유를 보여준다. 참가자의 실제 펀드 손익은 **본인의 매수 기준가와 보유 좌수**로 계산하므로 늦게 매수한 사람에게 장 시작 이후 수익을 소급 지급하지 않는다. 펀드 청약·환매는 개장 중에만 즉시 체결하고, 주식 주문과 동일한 계좌 잠금·장 상태 검사를 적용한다.

펀드 모델은 공개된 가격 버전에서 판단하고 해당 버전의 가격으로만 체결한다. 모델 주문은 다음 가격 구간의 수급 집계에 반영한다. 아직 공개되지 않은 다음 가격이나 사건을 모델이 미리 알 수 없도록 가격 갱신과 모델 판단 순서를 고정한다. 참가자 거래와 모델 거래의 가격은 같은 버전 기준이며 모델도 마감 후 거래할 수 없다.

UI에는 “AI 에이전트 펀드”라는 기획상의 이름과 함께 **규칙 기반 자동 운용**이라고 명시한다. 실제 AI 모델 또는 생성형 AI가 판단하는 것처럼 설명하지 않는다. 외부 AI API 키·유료 호출·LLM 장애 복구는 범위에 포함하지 않는다.

## 마감과 시상

총자산은 현금 + 주식 평가액 + 펀드 평가액이다. 수익률은 `(총자산 − 1,000,000) / 1,000,000`이다. 공부 보상과 추가 입금이 없으므로 모든 참가자의 기준 원금은 같다. 현금 이자도 없다.

장 마감 때 마지막 유효 가격과 펀드 기준가로 확정 평가하고, 참가자별 잔고·보유·수익률·순위를 스냅샷에 저장한다. 보유 자산은 평가만 하며 강제 매도하여 추가 수급을 만들지 않는다. 다음 장과 과거 결과 조회는 이 스냅샷을 사용한다.

시상 순서는 수익률 내림차순이며 내부 비교에는 부동소수점 반올림 값을 사용하지 않는다. 제안값으로 정확히 동률이면 해당 장 첫 체결 시각이 빠른 참가자, 그래도 같으면 장 참가 계좌 ID 순으로 결정해 시상 인원이 3명을 넘지 않게 한다. 참가 전 이 규칙을 안내한다. 실격자는 제외하고, 적격 참가자가 3명 미만이면 있는 인원만 발표한다.

실격 처리는 장별로 관리한다. 마감 후 실격 사유를 추가하면 원본 결과는 보존하고 수정된 시상 결과 버전을 별도 저장한다. 운영자가 확인한 최신 버전을 송출 화면에 표시한다.

## 화면과 시각 방향

색상은 어두운 숲·화석색 바탕에 따뜻한 호박색 강조를 제안한다. 종목 상승은 빨강, 하락은 파랑으로 유지한다. 차트와 자산 숫자의 가독성을 우선하고 공룡·귀신 연출은 제목, 아이콘, 사건 배너에 집중한다. 작은 모바일 화면에서는 장 상태·내 현금·거래 버튼이 우선이다. 운영 중 과한 번쩍임이나 배경 애니메이션은 사용하지 않는다.

참가 흐름은 `QR → 닉네임 참가 → 장 확인 → 직접 매매/펀드 → 내 자산 → 장 결과`다. 시장 상단에는 세 장의 시간표, 현재 시대, 남은 시간, 연결 상태가 있다. 본문에는 종목별 현재가·장 시작 대비 변화·시간 차트, 공룡 속보와 사건 내역이 있다. 펀드 화면에는 세 운용 성향과 기준가·장 수익률·구성 비중·청약/환매가 있다. 내 자산은 주식과 펀드를 분리해 표시하고 합산 수익률을 보여준다. 랭킹 기본값은 해당 장 수익률이다.

부스 송출 화면은 로그인 없이 조회 전용으로 연다. 6종목 차트, 현재 장·마감 카운트다운, 최신 사건, 수익률 상위 참가자와 참가 QR을 함께 표시한다. 휴장에는 직전 장의 확정 1–3위와 다음 장 시작 시각, 최종 종료 뒤에는 3개 장 결과를 표시한다. 실제 QR은 배포 주소 설정값으로 생성하고 localhost를 운영 QR로 고정하지 않는다.

관리자는 장 자동 운영 상태, 다음 장 일정, 지연/일시정지, 수동 재개, 뉴스·섹터 사건, 펀드 구성과 최근 결정, 장별 참가자·실격·시상 결과, 감사 로그를 확인한다. 수동 개입도 잠금과 중복 실행 방지를 거치며 이미 확정된 장을 초기화하는 일반 버튼은 제공하지 않는다. 별도 QA 모드에서만 장별 시드·가속 시계로 반복 검증한다.

화면 시안은 별도 로컬 미리보기이며 예시 가격·순위를 명시한다. 시안을 승인하더라도 예시 수익률과 뉴스가 실제 게임 결과로 들어가지는 않는다. 실제 제품 구현은 이 설계 승인 뒤 진행한다.

## 데이터와 API 경계

새 부스 영역에는 장, 참가자, 장별 계좌, 주식 보유, 주문, 구간 가격, 사건, 펀드 정의·모델 계좌·모델 주문·좌수 보유·청약환매 내역, 결과 스냅샷이 필요하다. 모든 금융 상태는 장 ID로 격리한다. 가격에는 날짜뿐 아니라 장 ID·구간 번호·공개 시각을 저장한다. 장별 계좌는 참가자·장 조합이 유일하다.

공통 도메인 계산을 기존 서비스에서 추출하되 기존 일일 이벤트의 공개 API 응답을 새 의미로 조용히 재해석하지 않는다. 부스용 API 네임스페이스와 응답 타입을 두고 새 프론트엔드에서 연결한다. 통합 현황에는 서버 시각, 장 상태, 장 ID, 가격 버전, 종목·펀드 시세, 사건, 순위를 넣는다. 주문·청약에는 장 ID와 요청 식별자를 받고 재시도 시 중복 체결하지 않는다. 서버 체결 가격 버전과 실제 금액을 응답한다.

동시성 잠금은 가격 갱신·일반 주문·펀드·마감이 같은 순서로 획득하도록 통일한다. 여러 계좌를 만지는 작업의 잠금 순서는 계좌 ID 기준으로 고정한다. 펀드·사건 처리 실패는 해당 트랜잭션을 롤백하고, 일시정지 상태에서는 새로운 주문을 받지 않는다. 조회는 마지막 커밋된 버전을 유지한다.

## 검증과 완료 조건

- 3개 장 개장·마감 경계와 저녁 휴장 중 주문 차단, 장별 시드 1회 지급과 계좌 격리를 검증한다.
- 잔고 초과 매수·초과 매도·실격자 거래·다중 요청·마감 경합에서 자산 불변식을 검증한다.
- 동일 구간 재실행과 다중 스케줄러가 가격·사건·펀드 매매를 중복 생성하지 않는지 검증한다.
- 공개 가격만 사용하는 펀드 판단, 청약/환매 반올림, 늦은 매수자의 수익률, 직접 투자와 펀드 평가액 합산을 검증한다.
- 섹터 충격 적용 범위, 운석 사건 1회 처리, 장 마감 이후 시세·랭킹 불변과 결과 이력을 검증한다.
- 프론트엔드 타입 검사·관련 사용자 동작 테스트·빌드, 백엔드 lint·타입 검사·관련 도메인/API 테스트를 실행한다. 모델 변경에 대한 Alembic 마이그레이션도 검증한다.
- 장 전체 가격 경로를 시뮬레이션해 펀드가 항상 이기거나 단일 사건이 모든 결과를 결정하는지 확인한다. 분포 확인 없이 수익률 균형이 검증되었다고 주장하지 않는다.
- 약 80명 참가의 폴링·동시 주문 부하를 확인한다. 실제 PostgreSQL 검증과 전체 배포 스택 검증은 실행 환경이 가능한 범위와 미검증 범위를 분리해 보고한다.
- 모바일과 부스 송출 화면을 브라우저로 확인한다. 사용자 데이터가 없는 신규 DB와 기존 이벤트 데이터가 있는 DB의 마이그레이션을 모두 고려한다.

부스 예산·간식 구매·경품 주문·현장 시상 전달·공개 배포와 외부 공지는 이번 코드 변경 범위에 포함하지 않는다.
